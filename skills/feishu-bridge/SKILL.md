## 何时使用

- 用户消息来自飞书（feishu-bridge 桥接），或上下文表明在飞书里协作
- 用户要求把某个文件/文档/报告/代码/日志作为【真实文件】发过去（不是粘贴内容）
- 任务执行中需要用户做选择、补充信息、确认方案（用 question 工具）
- 需要请求工具授权（用 permission 工具）
- 需要向用户说明可以使用的飞书本地命令

## 一、发送文件给飞书用户（feishu_send_file）

通过 MCP 工具 `feishu_send_file` 把文件作为真实文件消息发送。

- 调用时机：用户明确要“发文件/发给我/把 xx 发到飞书”时使用，**不要**在普通问答里误用
- 参数：`path` = 文件的**绝对路径**
- 约束：路径必须在**当前工作目录**内；单文件 ≤ 20MB
- 效果：桥会上传并作为飞书文件消息发出；成功后只需用一句话告知用户即可，不要在正文里粘贴文件全文
- 若路径不在工作目录内：先在本地把文件复制/生成到工作目录内，再调用

示例：用户说“把 TODO 文件发我”，先确认文件绝对路径（如 `/current/workdir/TODO.md`），再调用 `feishu_send_file`，最后回复“已发送 TODO.md”。

## 二、向用户提问 / 请求授权（question / permission）

任务中需要用户输入时，直接调用 question 工具：

- 桥会把它渲染成飞书**蓝色交互卡片**（选项按钮 + 说明）
- 用户可点按钮，也可直接回复编号（如 1）、选项文字或自定义内容
- 多选用逗号分隔；多条问题用分号或换行分隔
- 问题尽量给 2-5 个明确选项；需要自由输入时说明“可直接输入内容”

请求工具授权时调用 permission 工具：

- 桥会渲染成飞书**橙色授权卡片**（允许一次 / 始终允许 / 拒绝）
- 用户点按钮或回复“允许一次 / 始终允许 / 拒绝”

注意：提问/授权要克制，一次尽量合并成一条；用户在飞书端回复后任务会自动继续。

## 三、可提示用户的飞书本地命令

以下命令由桥本地处理，不消耗模型额度，需要时可在回复中建议用户使用：

- `/m` 或 `/menu`：打开菜单卡片（常用命令一键执行）
- `/help`：完整指引
- `/new`：保留当前工作目录开新会话；`/new <目录>` 切目录开新会话
- `/reset`：回到默认工作目录开新会话
- `/session`：查看当前会话；`/session <编号|id>` 切换/恢复会话
- `/sessions`：会话列表
- `/model` / `/models`：查看/切换模型
- `/status`：会话、目录、队列与任务状态
- `/stop`：本地停止转发当前任务进展
- `/restart`：重启桥服务

## 四、其他需要注意的行为

- 任务进度与结果会自动回传飞书：单轮快答只发一条“任务完成”，长任务先发“任务持续中”再原地更新为完成
- 所有文件操作默认发生在用户当前绑定的工作目录内，不要访问目录外路径（除非用户明确要求且已切到该目录）
- 外部通过 `opencode attach` 在同一会话发起的任务，其进展也会转发到飞书（带同一会话上下文）
- 用户可能在飞书只回复简短文本或编号，回答时按对应场景理解即可
